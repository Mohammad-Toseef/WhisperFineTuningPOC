## ✅ The false-negative guard cleared

`inspect_adapter.py --compare` on the saved adapters:

| | encoder median ΔW | decoder median ΔW | inert modules |
|---|---|---|---|
| round 1 | **0.000e+00** | 8.135e-05 | 192 / 512 (whole encoder) |
| round 3 | **5.088e-05** | 9.204e-05 | **0 / 512** |

**encoder / decoder median ΔW = 0.55×.** The encoder moved at a real magnitude, so
**1e-5 was not too low** — which is what makes the result interpretable. A flat
outcome could no longer be blamed on under-training.

`--compare` previously reported only *changed vs identical*, which is binary and
cannot answer "did it move *enough*" — a tensor shifting in the twelfth decimal
counts as changed. Added `ΔW = (α/r)·B@A` magnitudes per half.

### 🐞 A false alarm, recorded because it nearly became a finding

The first run of that comparison reported **77 inert modules** and 0.58×. Both
wrong: the safetensors file was still being written and `safe_open` memory-maps, so
unflushed regions read as zeros. **The file had already reached its final byte
count**, so a size check would not have caught it — only waiting for the transfer
to *exit* did. Inspect adapters only after the download process has exited.

**Criterion 1 ★ met** — `b3/nastaliq_only` CER **2.21** vs the 2.45 bar, −9.8% rel,
best this metric has reached.

**Criterion 2 ★ missed** — Set A CER **4.06** vs a 3.96 bar, +2.5% rel. Localised
entirely to `r1/nastaliq_only` (3.57 → 3.95); every other Set A bucket improved.

**Criterion 3 ★ not confirmed — the round's actual hypothesis.** Mis-hearing on
Set B fell 544 → **495 (−9.0%)** while *total* scored errors fell **−8.5%**. Its
share of what remains barely moved: **44.2% → 43.7%**. The ambiguous `near_miss`
bucket improved *faster* (−11.9%).

So: **training the encoder made the model broadly better but did not do what the
diagnosis predicted.** Since the encoder demonstrably moved at real magnitude, the
*theory* was wrong, not the execution. This was the failure mode named in advance
in `round3/README.md`.

### The Set A regression, mechanically explained

| category | round 2 | **round 3** | Δ |
|---|---|---|---|
| **dropped** | 116 | **158** | **+36.2%** |
| **inserted** | 141 | **112** | **−20.6%** |
| misheard | 245 | **228** | −6.9% |

Round 3 **trades insertions for deletions** on Set A. A dropped word costs one word
error but *every character* of that word — so Set A WER improved (8.31 → 8.24)
while CER rose. Not a coincidence; the two metrics genuinely disagree here, and
that disagreement is the diagnosis.

## Tooling fixed this session

Each of these was a **silent** failure — the wrong answer with no error.

| script | bug |
|---|---|
| `progress.py` | `modal app logs` returns only the last **100 entries** and each tqdm redraw is one entry, so during a ~32 min eval the window held *only* eval bars. Correctly rejecting them left nothing, and the dialog read "no progress line yet" at 66% done. Now `--tail 3000` + a state cache that only moves forward. |
| `modal_app.py::evaluate` | Warned on a missing model then **fell through and saved** a results file *and* a predictions sidecar named after a model it never loaded — an empty artifact indistinguishable by filename from a real control. Now raises. |
| `download_playlist_audio.py` | `ignoreerrors=True` swallowed a 403 and the caller printed `✅ Saved`. Now verifies the file exists and raises if nothing downloaded. |
| `compare_transcribe.py` | Hardcoded **round 1's** model, so a "fine-tuned" demo transcript would have been round 1's under a filename claiming round 3. Added `--model-path`; the model name now goes in the output filename, and `_meta.json` merges across runs instead of overwriting. |
| `compare_transcripts.py` | `--transcribe` had no way to forward a model path. Added `--transcribe-model-path`. Also added YouTube links to the report so any disagreement can be checked against the audio. |
| `push_to_hub.py` | `--what adapter` left the repo **front page empty**. Added `--card`. CLI options come from `local_entrypoint`, not the `@app.function` — a param added only to `push()` is rejected as "No such option". |
| `inspect_adapter.py` | `--compare` was binary; added ΔW magnitudes (above). |
| `triage_errors.py` / `rescore.py` | Generalised from hardcoded base/r1/r2 to include r3; delta column is now r2→r3, the control comparison. |

### Operational gotchas

- **Git Bash rewrites POSIX paths.** `--model-path /data/model/...` arrived as
  `C:/Program Files/Git/data/model/...`. Round 2 ran these from PowerShell so it
  never surfaced. Fix: `MSYS_NO_PATHCONV=1` (or use PowerShell).
- **`modal volume get` on a directory** concatenates it into a single file. Fetch
  files individually.
- **`modal app logs` needs `--tail N`**; the default 100 entries is far too few.
- Ephemeral Modal apps are pruned, so round 2's live log is gone — but
  `trainer_state.json` in each checkpoint retains the full `log_history`.

### ⚠️ Keep — and why

- **`processed/dataset_r2` (19.08 GB)** — round 4's training data *and* the 720-clip
  eval split that makes every cross-round comparison possible. **The volume holds
  no raw audio** (`processed/` is only the two Arrow datasets, 47 files, all
  accounted for), so rebuilding means re-uploading ~4.6 GB from the local machine
  and re-running the builder. Keep while round 4 is live.
- **All three adapters (0.70 GB total)** — 1.5% of the volume. Deleting them saves
  nothing and costs the irreplaceable artifacts.
- **Round 1's merged model is the eval harness control.** Every round has
  validated the harness by re-running it and reproducing **10.50%** to the decimal
  before trusting a new number. Deleting it means round 4's control needs a
  6.18 GB re-download from HF first — a convenience cost, not a risk, since it is
  published. `rescore.py` can reproduce round 1's figures from saved predictions
  with no GPU, but that validates only the **scoring** code, not the **inference**
  path (generation config, dtype, processor). The full control catches both.

### Before deleting anything

**Round 1's adapter has never been pushed to the Hub** (volume + one Downloads
folder), and **round 2's adapter is single-copy on the volume** — no Hub, no local
backup. Push both before any deletion, so nothing anywhere drops to one copy.
Round 1 is currently the *best*-protected round; round 2 is the exposed one.
